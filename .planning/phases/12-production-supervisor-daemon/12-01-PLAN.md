## Technical Context & Invariant Constraints

1. **Dual-Layer Process Architecture:**
   - **Layer 1: Production Supervisor (`src/orchestrator/supervisor.py`)** runs as the persistent parent watcher. It spawns, monitors, and recycles the trading child process (`python main.py daemon`).
   - **Layer 2: Master Trading Orchestrator (`python main.py daemon`)** runs the asynchronous trading loop, event bus subscriptions, and order execution.
   - Crash isolation: If the trading child encounters an unexpected exception, segfault, or unhandled loop termination, the supervisor catches the exit code, logs diagnostics, enforces exponential restart backoff, and alerts the operator.

2. **Heartbeat & Resource Watchdog Thresholds:**
   - **Heartbeat Pulse:** Child writes a JSON heartbeat every 30.0 seconds to `data/telemetry/heartbeat.json` and a row in `orchestrator_state.db` (`heartbeat_journal`).
   - **Stale Timeout:** Supervisor flags any heartbeat older than 60.0 seconds (>2 missed pulse cycles) as hung/deadlocked and initiates a graceful restart sequence.
   - **Memory RSS Ceiling:** Supervisor tracks the child process memory working set. If RSS exceeds 512.0 MB, it warns via webhook, requests a graceful shutdown, and recycles the child process to prevent out-of-memory kernel termination.
   - **Crash Loop Circuit Breaker:** Max 5 unexpected restarts within a 15-minute sliding window. If breached, supervisor stops restarts, trips a high-priority alert, and prevents continuous crash loops from jeopardizing capital or flooding RPC endpoints.

3. **Graceful Termination & Signal Propagation:**
   - When supervisor receives termination signals (`SIGINT`, `SIGTERM`, `CTRL+C`, `CTRL+BREAK`), it forwards a termination request to the child process.
   - Child process receives 15.0 seconds to flush all open SQLite WAL transactions, persist open positions, unsubscribe from Helius WSS, and close connections cleanly.
   - If child does not exit after 15 seconds, supervisor escalates to `terminate()` and `kill()`.

4. **Reboot WAL & On-Chain SPL Reconciliation (`src/orchestrator/reconciliation.py`):**
   - Startup reconciliation checks `persisted_positions` against on-chain SPL token accounts via Helius RPC.
   - Discrepancy handling:
     - **Normal:** Position exists in WAL with balance > 0, matching on-chain balance -> Rehydrate state machine and resume timers.
     - **Downtime Liquidation:** Position exists in WAL, but on-chain balance is 0 -> Transition to `CLOSED`, log exit reason as `EXTERNAL_LIQUIDATION_DURING_DOWNTIME`.
     - **Orphan Holding:** Wallet holds SPL tokens with no matching active position in WAL -> Log alert warning `ORPHAN_SPL_TOKENS_DETECTED`, do not execute speculative trades without state context.

5. **Cross-Platform OS Service Templates:**
   - Provide Windows Task Scheduler / NSSM setup scripts for Windows 11/Server hosts.
   - Provide Linux systemd unit configuration for standard VPS deployments.
